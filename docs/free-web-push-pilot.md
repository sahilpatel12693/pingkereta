# PingKereta: Free Web Push first, optional WhatsApp
**Prepared 13 Nov 2026. No public production messaging is approved or enabled by this change.**

## The planned pilot experience
1. A vehicle owner joins an operator-approved pilot, installs the PingKereta Home Screen web app if using iPhone, and registers a vehicle using an invitation.
2. They tap **Enable free notifications** and explicitly accept notification permission.
3. The browser generates an encrypted push subscription. PingKereta stores that endpoint only against the owner's authenticated vehicle record. Neither scanner nor other users can see it.
4. The owner prints a PingKereta QR sticker for the vehicle. Someone else scans it and selects a predefined reason.
5. The backend submits a free Web Push alert to up to three registered owner devices. If all push endpoints fail or no push endpoint exists, the system can try **WhatsApp only when the owner separately verified and opted in**. Telegram/SMS are retained as legacy optional fallback.
6. Message submission/acceptance is not proof that the phone displayed or read the alert. Phone battery restrictions, notification settings, offline devices and push-service outages still apply.

**Fees:** The standards-based Web Push protocol carries no per-notification charge from PingKereta/Twilio. Netlify usage, domains and operational costs can still apply. Optional WhatsApp and OTP are billed by providers.

## iPhone / iPad checklist — essential
Apple supports Web Push for Home Screen web apps on iOS/iPadOS 16.4+.
- On iPhone, open **https://pingkereta.com** in Safari.
- Tap **Share → Add to Home Screen**, confirm the PingKereta icon.
- **Launch PingKereta from its Home Screen icon before registering.** The installed app may have separate cookies/storage from the Safari browser tab. Current owner authentication relies on same-browser credentials; registering first in Safari and then installing can strand the owner account.
- Register with an operator-issued pilot invitation, then tap **Enable free notifications** from inside the installed web app. Accept the system permission prompt.
- Test from a **second phone** scanning the vehicle's QR sticker. Check the device notification and owner history; do not treat 'push accepted' as proven screen delivery.
- If permission was denied, re-enable notifications through iOS Settings → Notifications → PingKereta. Check Focus mode/notification settings.
- Adding PingKereta to Home Screen is not the same as installing it from an app store; **no Apple Developer Program is required** for standards-based web push.

On Android/desktop with supported browsers, owners can enable push from the website over HTTPS (installing the PWA is optional in most supported browsers).

Official sources:
- https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/
- https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers

## Server setup for FREE Web Push
1. Import the standalone GitHub `sahilpatel12693/pingkereta` main branch into its own Netlify site.
2. In a secure local checkout, with Node.js 22, run `npm install`, then `npm run vapid`. This generates a permanent VAPID key pair; do this **once**. Do NOT share private key in GitHub, screenshots or chat.
3. In the new Netlify site's Environment Variables configure:
   - `PINGKERETA_VAPID_PUBLIC_KEY` (public browser subscription key)
   - `PINGKERETA_VAPID_PRIVATE_KEY` (secret, never in frontend)
   - `PINGKERETA_VAPID_SUBJECT` (such as `mailto:working-contact@your-business-domain.com`; use a real monitored email)
   - `PINGKERETA_PILOT_INVITE_SECRET` (cryptographically random, 32+ characters)
   - `PINGKERETA_DATA_ENCRYPTION_KEY` (64 hex characters of 32 random bytes, for optional protected phone details)
4. **Leave both** `PINGKERETA_ENABLE_LIVE=false` and `PINGKERETA_RELEASE_APPROVED=false` while preparing and validating. No Twilio or Meta setup is required for a Web Push-only preview or a separately approved free-push pilot.
5. After deploying, verify `/manifest.webmanifest`, `/sw.js`, `/api/health`, `/api/pingkereta/status`, HTTPS and mobile installation. In safe preview `/api/pingkereta/status` reports `mode:preview` and does **not** allow registration, subscription or real alert requests.
6. Only after privacy/security review and real-device testing, enable an **isolated operator-supervised pilot** with both release flags true. The supplied rate limit and duplicate-claim protections use read/modify/write storage, **not atomic durable locks**, so they are not suitable for an unrestricted public messaging service.
7. Pilot invitations generated by `npm run invite -- "JXX 1234" 60` are plate-bound but **not single-use** and do not verify legal ownership. Require a documented operator check.

**Important:** VAPID key rotation invalidates existing browser subscriptions. Back up the private key in a proper secrets manager, not in repository files.

## Web Push controls and API
- `GET /api/pingkereta/status` — safe channel readiness; public VAPID key exposed only for approved pilot.
- `POST /api/pingkereta/push-subscribe` — owner cookie, explicit permission/consent, validated trusted push endpoint; up to three devices.
- `POST /api/pingkereta/push-unsubscribe` — owner cookie; removes this device's endpoint.
- `GET /api/pingkereta/owner` — returns count of registered devices; never exposes endpoint/key.
- `POST /api/pingkereta/alert` — free push first; optional verified WhatsApp if no push endpoint accepts delivery; legacy alternatives last.
- `POST /api/pingkereta/owner-delete` — removes vehicle record and with it associated push subscriptions. Full retention/deletion and audit processes remain to be reviewed.

Privacy: notification body includes the reported reason but not the number plate or contact number. The actual owner dashboard is protected by a browser-bound session. Phone and browser push settings may independently suppress notification display.

## WhatsApp later (optional)
To enable optional WhatsApp, create a verified business sender and approved utility template in Meta/Twilio. Add Twilio SID, auth token, Verify service, sender, Content SID, callback URL to Netlify environment (NOT GitHub). Existing WhatsApp onboarding only becomes available after sender configuration. See `docs/meta-whatsapp-sunday-launch.md`.
